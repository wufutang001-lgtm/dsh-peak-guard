# 峰时守卫 · dsh-peak-guard

DeepSeek **峰时计费时段**自动冻结思考：不发起模型请求、不产生 token，等你说「继续」或者等进入谷时自动接着干。侧栏有一个独立面板，可以开关这项功能、查看状态，并**直接编辑冻结时段**。

按 DeepSeek 官方分时计费口径（北京时间 UTC+8）：

| 时段 | 判定 |
|---|---|
| 峰时 | 周一至周五（非法定节假日）**09:00–12:00、14:00–18:00** |
| 谷时 | 其余全部：12:00–14:00、18:00–次日 09:00、周末、法定节假日全天 |

区间左闭右开：09:00 整算峰时，12:00 整算谷时。

## 它怎么冻结

冻结发生在 `agent/pre-step`——回合内每「步」开始、认领收件箱的那一瞬。峰时这里直接返回 `{ kind: 'reject' }`，agent-loop 会把整个回合以 `blocked` 收口，**全程不发出模型请求**，所以峰时不烧一个 token。

被认领的消息会原样放回 `next-step`（按 id 去重），因此你的输入不会凭空消失——谷时唤醒后它们照常被处理。

## 三种恢复方式

1. **说一句就行**：下一条消息恰好是 `继续` / `继续任务` / `继续吧` / `峰时继续` / `强制继续` / `resume` / `continue`（大小写与首尾空白无关，最长 24 字符）。放行这一回合，并且**当前峰时窗口内不再冻结**。
2. **等谷时**：冻结时挂一个定时器到窗口结束 +1s，到点对还挂着输入的空闲会话发一条唤醒消息，自动续跑。
3. **手动**：面板「立即继续」、输入框上方的状态条、斜杠命令 `/peak resume`。

## 界面

侧栏底部有一个表盘图标（**峰时守卫**），点开是它自己的主面板，不占设置页：

- **顶部开关**：总开关。关掉立刻放行所有冻结中的回合，峰时也照常思考。
- **冻结时段**：按 30 分钟粒度编辑每天哪些区间算峰时（默认 `09:00–12:00`、`14:00–18:00`）。可加、删、改、恢复默认；改动只有点「保存」才生效，非法输入（空、倒序、重叠、超过 8 段）会被后端拒绝并给出原因。
- **当前状态**：现在是峰时/谷时、窗口、下次峰时、已暂停的回合与输入条数、豁免截止、状态文件位置。
- **立即操作**：`立即继续`（本窗口豁免）、`取消本次豁免`。

输入框上方还有一条状态条，只在峰时暂停或存在豁免时出现。

两处共用一个 20 秒轮询的 store，通过同源 HTTP 读 `GET /plugins/peak-guard/state`、写 `POST /plugins/peak-guard/action`（`set-enabled` / `set-windows` / `resume` / `clear-override`）。

## 斜杠命令

| 命令 | 作用 |
|---|---|
| `/peak` | 看状态 |
| `/peak on` / `/peak off` | 开关冻结功能（关掉会立刻放行所有冻结回合） |
| `/peak resume` | 立即继续，并在本峰时窗口内豁免 |
| `/peak freeze` | 取消豁免，重新开始冻结 |

## 配置

`cordis.patch.yml` 里的默认值，也可在插件配置里改：

```yaml
enabled: true          # 总开关初值
autoResume: true       # 谷时自动续跑
offsetMinutes: 480     # 时区偏移（480 = UTC+8）
windows:               # 峰时窗口，[起始小时, 结束小时)，支持 9.5 这样的半小时
  - [9, 12]
  - [14, 18]
holidays:              # 法定节假日：'YYYY-MM-DD' 或每年重复的 'MM-DD'
  - '2026-10-01'
```

节假日默认为空。**空的语义是"按峰时保守处理"**——不确定的日子宁可不省 token。周末永远算谷时（调休上班也算），不需要配置。

状态落在 `$DSH_HOME/peak-guard/state.json`（开关、**面板保存的时段**、本次豁免截止、暂停计数），重启后都保留。面板改过的时段优先于 `cordis.patch.yml` 里的 `windows`。

## 边界

- 冻结以**回合与步骤**为粒度：正在生成的那一段会自然结束，不会中途截断。
- 只能在 `agent/pre-step` 挡住「新的一步」。已经排进队列的工具调用会跑完。
- 冻结期间你发的新消息会留在会话的待处理队列里，**不会写进对话记录**——这是 `reject` 的设计结果（回合以 `blocked` 收口，没有 `user/message` 落库）。刷新页面后那几条输入可能看不见，但它们仍在队列中，谷时唤醒后会照常处理。所以峰时**别把重要内容只发一遍就刷新页面**。
- 进程重启不影响开关与时段，但冻结中的队列与定时器不跨进程保留（重启后输入还在会话历史里，只是不再自动唤醒）。
- 一天的峰谷判定按 `offsetMinutes` 固定偏移换算，未使用 IANA 时区数据库；换成有夏令时的时区需要自己改 `offsetMinutes`。
- **Host 半边改了代码需要重启 DSH 才生效**：运行中的宿主进程不会热替换已加载的 Host 模块（Web 半边刷新页面即可）。面板检测到旧版 Host 时会把时段设为只读并给出提示。

## 安装 / 卸载

```powershell
# 安装（进入插件目录后安装当前目录）
dsh plugin install .

# 或者直接指向任意路径
dsh plugin install /path/to/dsh-peak-guard
```

也可以直接让 Harness 里的 `plugin_manager install_bundle` 指向这个目录。装好后刷新页面：侧栏出现图标、面板可用、输入框上方出现状态条。卸载在「设置 → 插件」里停用或删除即可。

## 开发

```powershell
node tests\smoke.mjs    # Host 逻辑：reject / 收件箱还原 / 豁免 / 开关 / 路由 / 时段校验与持久化
node tests\client.mjs   # Web 半边：三个槽位注册、面板渲染、编辑与保存、状态条
```

两套测试都是用假 ctx / 假浏览器跑真代码，不需要 Harness 在跑。

文件：`host.js`（Host 半边，零依赖，只用 node 内置模块）、`client.js`（Web 半边，`window.__ModuleLoader__` 工厂）、`locale/`、`icon.svg`、`cordis.patch.yml`。
